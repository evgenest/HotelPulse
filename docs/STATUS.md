## Как продолжить в новой сессии

1. `git checkout claude/epic-cori-g8qizf && git pull`
2. Прочитать этот файл, план и `docs/adr/`.
3. .NET-тесты в облачной сессии: установить SDK (`dotnet-install.sh --jsonfile global.json`), запустить `dockerd`, затем `npm run test:unit` и `npm run test:integration`.
4. Следующая задача — пункт 9 этапа 1: переключатель бэкенда на фронте. Перед этим проверить, что job `laravel` в CI зелёный. Запуск тестов PHP: `docker run --rm -v $PWD/apps/api-laravel:/app -w /app <образ PHP 8.5 с pdo_pgsql, redis, pcntl, sockets, bcmath> ./vendor/bin/pest`.

### Известные ограничения облачной сессии (не проекта)

- Прокси сессии не отдаёт архивы GitHub (`api.github.com/.../zipball` → 403), но пропускает `git clone`. Поэтому composer здесь работает только с `--prefer-source` (медленно, 8 ГБ вместе с историями git; после установки `find vendor -name .git -prune -exec rm -rf {} +`).
- Из-за этого **Larastan не установлен**: `phpstan/phpstan` распространяется только архивом. **TODO:** на локальной машине или в CI выполнить `composer require --dev larastan/larastan` и закоммитить `composer.lock`.
- PHP 8.5 запускается в Docker-образе. Локальная сборка образа требует CA прокси, Dockerfile для этого лежит в scratchpad сессии, а не в репозитории.
- CI на GitHub таких ограничений не имеет.

## Журнал

- 2026-11-03 — feature-тесты Laravel: каталог, бронирования, отмена, worker/relay (включая «брокер недоступен» и повторную доставку), параллельные сценарии из .NET (10 POST → один 202, 10 с одним ключом → одно бронирование, отмена против worker'а). Итого 147 тестов, три прогона подряд без падений. Найдено при отладке: в Laravel фасад `Redis` без `use` указывает на класс расширения phpredis, а менеджер Redis читает конфиг один раз — для имитации сбоя нужен хелпер `breakRedis()`.

- 2026-11-03 — начат пункт 8: хелперы Pest (`stay`, `bookingBody`, `inParallel` через `pcntl_fork` — настоящие отдельные процессы), тесты каталога, бронирований и отмены.

- 2026-11-03 — relay и consumer Laravel. Проверено на живом стеке: пока RabbitMQ лежал, 3 строки outbox ждали неопубликованными; после восстановления все три опубликованы и обработаны, бронирование `confirmed` с кодом. SIGTERM: consumer завершился за 0,5 с, relay — за 0,1 с, оба доделав текущую работу. (В песочнице RabbitMQ запускается только с `--tmpfs /var/lib/rabbitmq` — проблема прав на `.erlang.cookie`, к проекту не относится.)

- 2026-11-03 — HTTP-слой Laravel. Проверено вручную на Postgres + Redis: все коды из таблицы API; `X-Cache` MISS → HIT; без Redis — BYPASS за 35 мс. Решение: проверку тела запроса делает перенесённый `BookingValidator` (тексты ошибок как в .NET), а не FormRequest — иначе было бы два набора правил.

- 2026-11-03 — репозитории Laravel: тот же SQL, что в .NET после фиксов этапа 0. Смоук на Postgres 18: повтор по ключу → исходное бронирование; ключ + другое тело → конфликт; пересечение → 409; отмена сохраняет шаги worker'а; CAS worker'а после отмены не срабатывает.

- 2026-11-03 — миграции Laravel. Найдено: `migrate --isolated` не защищает при кэше `array`. Сделана своя команда с advisory lock в Postgres, как в .NET. Проверено на Postgres 18: 6 таблиц, constraint `bookings_no_overlapping_stay`, 6 отелей; повторный запуск — «Nothing to migrate».

- 2026-11-03 — Domain перенесён: те же правила, тексты ошибок и формат JSON, что в .NET. Деньги считаются строками через bcmath, без float. Даты строго `yyyy-MM-dd`, несуществующие (30 февраля) отклоняются. Unit: 100/100, Pint чистый.

- 2026-11-03 — скелет Laravel: API-only (без views и фронтенд-сборки), подключения из тех же env-переменных, что у .NET, JSON-логи в stderr, Redis с таймаутом 250 мс и без повторов. CI #29 (повтор параллельных тестов) — зелёный.

## Как продолжить в новой сессии

1. `git checkout claude/epic-cori-g8qizf && git pull`
2. Прочитать этот файл, план и `docs/adr/`.
3. .NET-тесты в облачной сессии: установить SDK (`dotnet-install.sh --jsonfile global.json`), запустить `dockerd`, затем `npm run test:unit` и `npm run test:integration`.
4. Порт закончен. Что осталось (не блокирует):
   - ✅ **деплой на Render** выполнен: веб, .NET API и Laravel API работают, версия 1.1.2. Ничего обязательного не осталось.
 Запуск тестов PHP: `docker run --rm -v $PWD/apps/api-laravel:/app -w /app <образ PHP 8.5 с pdo_pgsql, redis, pcntl, sockets, bcmath> ./vendor/bin/pest`.

### Известные ограничения облачной сессии (не проекта)

- Прокси сессии не отдаёт архивы GitHub (`api.github.com/.../zipball` → 403), но пропускает `git clone`. Поэтому composer здесь работает только с `--prefer-source` (медленно, 8 ГБ вместе с историями git; после установки `find vendor -name .git -prune -exec rm -rf {} +`).
- Larastan в CI ставится обычно. Локально в этой песочнице `phpstan/phpstan` распространяется только архивом, поэтому три пакета (`phpstan/phpstan`, `larastan/larastan`, `iamcal/sql-parser`) кладутся в `vendor/` через `git clone` по версиям из `composer.lock` и дописываются в `vendor/composer/installed.json`; запуск — `php vendor/phpstan/phpstan/phpstan analyse`.
- PHP 8.5 запускается в Docker-образе. Локальная сборка образа требует CA прокси, Dockerfile для этого лежит в scratchpad сессии, а не в репозитории.
- CI на GitHub таких ограничений не имеет.

## Журнал

- 2026-11-03 — деплой на Render завершён. Проверено на живом стенде: Laravel `/health` 1.1.2, `/health/live`, `X-Cache` MISS → HIT, `X-Request-Id`, CORS для веба, бронирование 202 → `confirmed` за ~6 с, повтор на те же даты 409, отмена освобождает номер; .NET 1.1.2, бронирование → `confirmed`; веб получил оба адреса API, переключатель работает. Тестовые бронирования отменены.

- 2026-11-03 — первый деплой Laravel на Render упал: `exec /usr/local/bin/frankenphp: Operation not permitted`. Причина — файловая capability `cap_net_bind_service` у бинарника FrankenPHP в базовом образе; Render сбрасывает capabilities, и ядро отказывается запускать такой бинарник. Воспроизведено с `--cap-drop ALL`, исправлено `setcap -r` (порт 8080/`$PORT` её не требует). PR #16.
- 2026-11-03 — при подготовке деплоя найдено: замок миграций был сессионным (`pg_advisory_lock`) и в .NET, и в Laravel; через пул Neon он мог остаться висеть и повесить следующий деплой. Теперь транзакционный замок в открытой транзакции на отдельном подключении; `DATABASE_URL_UNPOOLED` стал необязательным. Тесты: .NET 28/28, Laravel 149/149. Версия 1.1.2.

- 2026-11-03 — у владельца сервисы на Render созданы вручную, без Blueprint. В DEPLOY.md добавлен путь «Without a Blueprint»: один новый web-сервис для Laravel с точными настройками; к работающим сервисам Blueprint не подключаем (риск дублей).

- 2026-11-03 — подготовка деплоя. Найдено: в документации стояло «отдельная **ветка** Neon `laravel`», но ветка Neon копирует таблицы и данные родителя — миграции Laravel упали бы, и Laravel видел бы бронирования .NET. Исправлено на отдельную **базу** `hotelpulse_laravel` (DEPLOY.md, render.yaml, спека, план). Проверено: строка подключения Neon (`postgresql://…-pooler…?sslmode=require&channel_binding=require`) разбирается Laravel верно; контейнер в режиме `all` при лимите 512 МБ (как у бесплатного Render) — 222 МБ в простое, 235 МБ под нагрузкой, без перезапусков.

- 2026-11-03 — Octane + FrankenPHP. Найдено: без `APP_KEY` воркер Octane падает при старте, а Octane не показывает причину (под FrankenPHP нет константы `STDERR`, и его обработчик ошибок сам падает). Видно только «worker has not reached frankenphp_handle_request()». Решение: стартовый скрипт контейнера проверяет `APP_KEY` и пишет понятную ошибку.

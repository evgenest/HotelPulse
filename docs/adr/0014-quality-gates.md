# ADR-0014. Качество проверяется автоматически: спека → тесты → CI

**Статус:** принято (с версии 1.0.0; Laravel и параллельные тесты ×3 — с 1.1.0; статический анализ и нагрузочный тест — с 1.1.1)

## Контекст
Две реализации одного API, правила конкурентности, которые легко сломать незаметно, и работа вместе с AI-агентом (Claude Code), который пишет много кода быстро.

## Проблема
- «Работает у меня» и «работало вчера» ничего не гарантируют.
- Гонки [[16]](glossary.md#t16) не видны в обычных тестах: запросы там идут по очереди.
- Даже параллельный тест ловит гонку не каждый раз: deadlock из ADR-0005 появлялся примерно в каждом третьем запуске.
- Две реализации со временем расходятся, если их ничто не держит вместе.
- AI-агент без явных правил может, например, заменить проверку в SQL на «прочитал → проверил → записал».

## Решение
- **Сначала спецификация** [[63]](glossary.md#t63): `docs/specs/`. Каждая строка таблицы «случай → ответ» — отдельный тест.
- **Тесты на настоящих сервисах** [[28]](glossary.md#t28): Postgres, Redis и RabbitMQ запускаются в Docker, без подделок.
- **Параллельные тесты** в настоящих отдельных процессах, в CI — **три прогона подряд**.
- **Ворота качества** [[62]](glossary.md#t62) в CI на каждый push: тесты обеих реализаций, проверка типов фронтенда, стиль кода (Pint), уязвимости (`composer audit`), статический анализ PHP (Larastan [[48]](glossary.md#t48), уровень 8, без исключений), сборка всех Docker-образов.
- **Нагрузочный тест** [[55]](glossary.md#t55) (k6) с порогами из спеки и проверкой базы после прогона. Запускается вручную перед релизом, результаты в [`docs/benchmarks.md`](../benchmarks.md).
- **Автоматические проверки согласованности**: одинаковые SQL-файлы схемы, одна версия продукта во всех местах.
- **Правила для AI-агента** в `CLAUDE.md` (корневой и `apps/api-laravel/CLAUDE.md`): что нельзя ломать и почему, со ссылками на ADR.

## Последствия
- Именно параллельные тесты нашли две настоящие ошибки (ADR-0004, ADR-0005), которые прошли бы мимо обычных тестов.
- Статический анализ на первом прогоне нашёл 60 замечаний, среди них настоящие: конфиг, ссылавшийся на удалённый класс, и чтение строк из базы без проверки типов. Все исправлены, а не скрыты.
- Нагрузочный тест подтвердил корректность под всплеском в обеих реализациях: 0 ошибок 5xx, 0 двойных бронирований, 0 зависших.

## Коротко, своими словами
> «Готово — это когда CI зелёный. Сначала спека, каждая её строка — тест, тесты идут на настоящих сервисах, гонки ловим параллельными тестами несколько раз подряд. Правила, которые нельзя ломать, записаны для людей и для AI-агента.»

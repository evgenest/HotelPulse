# ADR-0013. Безопасность по умолчанию

**Статус:** принято, в обеих реализациях (1.1.0). `APP_KEY`, `composer audit` и Octane относятся только к Laravel.

## Контекст
Аутентификации в демо нет (это вне рамок), но всё остальное должно быть безопасным по умолчанию: ошибиться должно быть трудно.

## Проблема
Типичные утечки и дыры MVP:
- пароль от базы закоммичен в репозиторий;
- включён режим отладки, и клиент видит трассировку ошибки с кусками кода и путями;
- контейнер работает от root;
- CORS [[46]](glossary.md#t46) открыт для всех;
- в логах имена гостей [[44]](glossary.md#t44);
- один клиент может засыпать API запросами.

## Решение
| Мера | Как |
|---|---|
| Секреты только из переменных окружения | в репозитории нет ни одного пароля или ключа; `.env` в `.gitignore`; ключ Laravel в CI генерируется на каждый прогон |
| Без ключа — не стартуем | контейнер Laravel без `APP_KEY` [[47]](glossary.md#t47) сразу падает с понятной ошибкой |
| Отладка выключена | ошибка 500 возвращает только `{"error":"Internal server error."}` (Laravel: `APP_DEBUG=false`; .NET: свой обработчик исключений); заголовка `Server` нет |
| Не root | все образы API и worker'а работают от непривилегированного пользователя (.NET — `app` из официального образа, Laravel — свой `hotelpulse`) |
| CORS по списку | только адреса из `CORS_ORIGINS` (найдена и исправлена ошибка, из-за которой список молча не применялся) |
| Без персональных данных в логах | тело запроса и имя гостя не логируются |
| Rate limit [[45]](glossary.md#t45) | не больше 30 бронирований в минуту с одного IP; счётчик общий для всех копий API (в Redis); при недоступном Redis — fail-open [[58]](glossary.md#t58), потому что доступность важнее лимита |
| Заголовки | `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer` |
| Уязвимости зависимостей | `composer audit` в CI |

## Альтернативы
- **Rate limit fail-closed** — надёжнее против атаки, но тогда сбой кэша превращается в отказ сервиса, а это противоречит правилу «Redis не роняет запросы». Для настоящей защиты от атак лимит ставят ещё и на уровне прокси или WAF.

## Последствия
- Безопасность не зависит от того, не забыл ли кто-то что-то настроить: небезопасный запуск просто не стартует или не пропускает.
- Следующие шаги: аутентификация (Sanctum [[51]](glossary.md#t51)) и мультитенантность с RLS [[50]](glossary.md#t50) описаны в спеке как путь к продакшену.

## Коротко, своими словами
> «Секреты только из окружения, без ключа не стартуем, отладка в продакшене выключена, процессы не от root, CORS по списку, персональных данных в логах нет, а один клиент не может завалить API запросами.»

## Где в коде
- Laravel: `docker/entrypoint.sh`, `Dockerfile`, `bootstrap/app.php`, `config/cors.php`, `app/Http/Middleware/`
- .NET: `apps/api/Program.cs` (CORS), `apps/api/Middleware.cs`, `apps/api/Endpoints.cs` (`LimitBookings`), `Caching/BookingRateLimiter.cs`, `apps/*/Dockerfile`

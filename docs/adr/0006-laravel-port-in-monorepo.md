# ADR-0006. Laravel-версия в этом же репозитории, хостинг на Render через Docker

**Статус:** принято 2026-11-03. План — [plans/laravel-port.md](../plans/laravel-port.md), ход работ — [STATUS.md](../STATUS.md).

## Контекст
Хочу показать работу на PHP/Laravel на проекте, который уже есть, и честно сказать, что изучаю Laravel на нём.

## Проблема
- Где держать вторую версию бэкенда, чтобы это не выглядело как подгонка под вакансию?
- Где бесплатно захостить PHP? Сейчас в .NET API и worker работают в одном процессе, а в PHP так не принято.

## Решение
- **Один репозиторий** (монорепо [[29]](glossary.md#t29)): папка `apps/api-laravel/` рядом с `.NET`. Фронтенд общий, и на нём есть переключатель «.NET / Laravel». Описание API общее, тесты проверяют одни и те же сценарии. Подача: «одна спецификация — две реализации».
- **Данные раздельно:** у каждой версии своя база, своя очередь и свой префикс в кэше. Иначе версии будут перехватывать письма друг друга.
- **Хостинг:** Render, бесплатно, через Docker [[30]](glossary.md#t30). PHP там можно запустить только в Docker. Внутри контейнера supervisord [[30]](glossary.md#t30) запускает веб-сервер, worker и relay.
- **Версии:** PHP 8.5.x (обновления 8.5 ставятся сами, на 8.6 переходим вручную после проверки), Laravel 13.39+, остальные пакеты — последние стабильные.

## Альтернативы
- **Отдельный репозиторий** — выглядит чище для PHP-вакансии, но фронт придётся дублировать, и сравнения не будет.
- **Laravel Cloud** — от  в месяц, бесплатного тарифа нет.
- **Fly.io** — удобнее для Laravel, но тоже платно, примерно –5 в месяц.

## Последствия
- Все правила из ADR-0001…0005 переносятся в PHP один в один. Главное: в Laravel **не** менять статус через `$booking->save()` после чтения (это «прочитал → записал», гонка [[16]](glossary.md#t16)). Только UPDATE с условием в WHERE [[17]](glossary.md#t17).
- В CI появится вторая проверка — для PHP.

## Как объяснить на собеседовании
> «Чтобы освоить Laravel, я перенёс свой .NET-проект: та же спецификация, тот же фронт, те же тесты. Так видно, что я понимаю идеи — транзакции, outbox, идемпотентность — а не только синтаксис одного фреймворка.»

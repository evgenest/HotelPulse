# ADR-0006. Laravel-порт в том же репозитории, хостинг на Render через Docker

**Статус:** принято 2026-11-03. Работа идёт по [плану](../plans/laravel-port.md), статус — в [STATUS.md](../STATUS.md).

## Контекст
Нужно показать владение PHP/Laravel (вакансия: Laravel + Vue, Spec-Driven Development, AI-агенты) на проекте, который уже есть, не выдавая порт за давний опыт.

## Решение
- **Монорепо.** `apps/api-laravel/` рядом с `apps/api` (.NET). Один Nuxt-фронт с переключателем бэкенда, один контракт `docs/api.md`, одинаковые сценарии тестов. Порт становится фичей проекта («одна спека — две реализации»), а не подгонкой под вакансию. В README честно написано: Laravel осваивается на этом проекте.
- **Данные изолированы.** Отдельная ветка или база Neon, отдельная очередь RabbitMQ, префикс ключей Redis. Иначе два relay опубликуют одни и те же строки outbox, а consumer одного стека заберёт сообщения другого.
- **Версии.** PHP `~8.5.12` (патчи ставятся автоматически, переход на 8.6 — вручную после changelog). `laravel/framework:^13.39`. Остальное — последние стабильные версии с `^`, lock-файлы коммитятся.
- **Хостинг.** Render free, Docker. Нативного рантайма PHP у Render нет. В одном контейнере supervisord запускает веб (слушает `$PORT`), `queue:work` и outbox relay. Это аналог `RUN_WORKER_IN_PROCESS` в .NET.

## Рассмотренные альтернативы
- **Отдельный репозиторий** — чище для отклика именно на PHP, но фронт и контракт дублируются, а сравнения стеков нет.
- **Laravel Cloud Starter** — $5 в месяц плюс оплата за использование, бесплатного тарифа нет.
- **Fly.io** — process groups `app` и `worker` удобнее supervisord, но бесплатного тарифа нет (только trial), а Managed Postgres стоит от $38. Остаётся платным вариантом за $2–5 в месяц.

## Последствия
- Правила из ADR-0001…0005 переносятся в PHP один в один. Запрещено менять статус через `$model->save()`. Разрешены условный `update()` с проверкой числа изменённых строк и `UPDATE ... RETURNING`. `QueryException` с кодом `23P01` → 409.
- В CI появится второй job (PHP).

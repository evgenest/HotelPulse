# ADR-0008. Кэш ускоряет чтение, но система работает и без него

**Статус:** принято (с версии 1.0.0)

## Контекст
Каталог отелей и доступность номеров читают намного чаще, чем меняют. Redis [[26]](glossary.md#t26) снимает эту нагрузку с Postgres.

## Проблема
Наивный кэш создаёт три типичные беды:
1. **Устаревшие данные.** Комнату забронировали, а кэш ещё минуту показывает «свободно».
2. **Сложная инвалидация.** Нужно найти и удалить все ключи, где упоминается отель (каталог, карточка, доступность на все комбинации дат).
3. **Кэш стал точкой отказа.** Redis упал, и весь сайт отдаёт ошибки, хотя база жива.

## Решение
- **Postgres — источник истины, Redis — только для чтения.** В кэш никогда не пишется то, чего нет в базе.
- **Версионированные ключи** [[57]](glossary.md#t57). Каждая запись, которая меняет доступность (создание, отмена, подтверждение или отказ worker'ом), увеличивает версию отеля и каталога. Старые записи никто не читает, они исчезают по TTL [[56]](glossary.md#t56) через 60 секунд.
- **Fail-open** [[58]](glossary.md#t58). Любая ошибка Redis (недоступен, таймаут) → ответ из Postgres с заголовком `X-Cache: BYPASS`. В Laravel-версии таймаут подключения 250 мс и без повторов, чтобы запрос не висел, ожидая мёртвый Redis.
- Заголовок `X-Cache: HIT | MISS | BYPASS` показывает, откуда ответ: это удобно при отладке.

## Альтернативы
- **Удалять ключи по шаблону** (`KEYS`/`SCAN`) — медленно и опасно на большом Redis.
- **Короткий TTL без инвалидации** — проще, но данные устаревают на весь TTL.
- **Писать в кэш при записи** (write-through) — кэш и база могут разойтись при сбое между двумя записями.

## Последствия
- После бронирования следующий запрос сразу видит свежие данные (проверено тестом `invalidates the hotel cache…`).
- Выключенный Redis не роняет ни одного запроса (тест `BYPASS when Redis is down`, ручная проверка: 200 за 35 мс).
- Устаревшие версии какое-то время лежат в памяти Redis, пока не истечёт TTL.

## Коротко, своими словами
> «Кэш — оптимизация, а не зависимость. Источник истины — база. Инвалидация — это просто увеличить номер версии в ключе. Если Redis лёг, читаем из базы и помечаем ответ BYPASS.»
